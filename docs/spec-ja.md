本書は、Claude Code に対する開発指示である。
仮の名称として `carbonroute` を用いる。
名称の確定は開発者の判断に委ねる。

## 0. この文書の読み方

第1章から第4章は、何を作るのかと、なぜその形なのかを定める。
第5章以降が実装の仕様である。

実装の判断に迷ったときは、第2章の設計原則に戻って決めること。
原則と仕様が衝突する場合は、原則を優先し、その旨を issue として記録すること。

## 1. 背景

### 1.1 温室効果ガスの定量は反応式では決まらない

化学品の温室効果ガス排出量は、**ライフサイクル評価**（LCA、原料採掘から製造や廃棄までの物質とエネルギーの流れを追い、環境影響に換算する手法）の枠組みで定量するのが標準である。
規格としては ISO 14040 と ISO 14044 が手順を、ISO 14067 が製品単位のカーボンフットプリント算定を定める。
化学産業向けの業界ルールとして TfS の PCF ガイドラインがある（https://www.tfs-initiative.com/product-carbon-footprint-pcf ）。

反応式から機械的に読み取れるのは、化学量論として二酸化炭素が発生する反応の直接排出分と、原子経済性のような質量効率だけである。
排出量の大半は原料の上流製造とエネルギー供給に由来するため、反応式だけでは判定できない。

質量指標を環境影響の代理として使う運用の限界は、定量的に検証されている（Green Chem. 2025, https://pubs.rsc.org/gc/article/27/34/10153/894005/ ）。
レテルモビル合成を対象に LCA と PMI を並行適用した研究では、両ルートとも溶媒が温室効果への最大の寄与であり、質量に対して不釣り合いに大きい触媒の負荷を PMI が捉えられなかったと報告されている（J. Am. Chem. Soc. 2025, 147, 40944, doi:10.1021/jacs.5c14470）。

### 1.2 既存ツールの分布と、空いている隙間

部品はすでに揃っている。

- AI4Green：オープンソースの電子実験ノート。反応を入力するとグリーン指標を自動計算する（doi:10.1021/acs.jcim.3c00306, https://github.com/AI4Green/AI4Green ）
- PMI Predictor：提案ルートの効率をラボ検証の前に予測する（Nat. Sustain. 2019, doi:10.1038/s41893-019-0400-5）
- Brightway と openLCA：汎用の LCA 計算基盤（https://brightway.dev/ ）
- ecoinvent、USLCI、EF：背景データベース

空いているのは、これらをつなぐ配管である。
既存のグリーン指標ツールは単一反応を対象としたものが多く、合成ルート全体の評価への適用は難しいと指摘されている（https://www.sciencedirect.com/science/article/pii/S2452223622000359 ）。
反応式から影響評価までを、前提を固定したまま一本で通す層が存在しない。

### 1.3 完全な自動化が成立しない理由

自動化を阻む要因は三層に分かれる。

第一層はデータの欠落である。
新規素材は背景データベースに載らず、実験記録は自由記述に散らばっている。
機械的な作業が大半を占めるため、自動化の効きが最も大きい。

第二層は規模の外挿である。
実験室の溶媒使用量や加熱効率は工業規模とかけ離れており、補正には別のモデルが要る。
標準化された方法は存在しない。

第三層は前提の選択である。
システム境界、配分規則、電力の排出係数、GWP の時間地平、溶媒回収率。
これらは事実ではなく約束事であり、対象ごとの判断が必ず残る。

本ツールは第一層を自動化し、第三層を明示的に人へ差し戻す。
第二層は v0 の対象外とする。

### 1.4 AI エージェントの位置づけ

汎用の大規模言語モデルを根拠づけなしに使う危険は測定されている。
17 名の実務者が 11 のモデルを 22 の LCA 関連タスクで評価した結果、回答の 37 パーセントに不正確または誤解を招く内容が含まれ、引用の捏造率が最大 40 パーセントに達したモデルもあった（arXiv:2510.19886, https://arxiv.org/abs/2510.19886 ）。
同じ研究は、根拠づけの仕組みを伴えば説明生成や単純作業の省力化に有用だとも述べている。

この結果を受けて、本ツールは v0 において言語モデルを計算経路に一切含めない。

## 2. 理念

以下は設計原則であり、実装判断の基準となる。

**順位を返し、絶対値を主要指標にしない。**
問いを「このルートの排出量はいくつか」から「A と B のどちらが低く、どのくらい確からしいか」へ移す。
両ルートで共通する原料や工程は差をとれば相殺されるため、解決すべきデータが大幅に減る。

**前提を一箇所に集約する。**
人が決める事柄はすべて入力ファイルの `assumptions` 節に置く。
それ以外の処理は決定論的であり、同じ入力から必ず同じ出力を返す。

**値の出所を混ぜない。**
一次データ、供給者提供値、背景データベース、構造推定、類似物代替。
どの段階で埋めた値かを個々に保持し、集計後も追跡できる形で出力する。

**判定不能を返せる。**
不確実性が大きく順位が決まらない場合、無理に一つの数字を出さず、判定不能と、順位を決めるために必要な情報を返す。

**公開データだけで動く。**
ecoinvent は商用ライセンスで提供されており、データを同梱した配布はできない。
既定の動作は再配布可能な公開データのみで完結させ、商用データベースは任意のアダプタとして扱う。

**精度ではなく検証可能性で勝負する。**
公開データのみで到達できる精度には上限がある。
その上限を隠さず文書化し、代わりに第三者が同じ結果を再現できる状態を保証する。

## 3. 差別化ポイント

| 観点 | 既存のグリーン指標ツール | 汎用 LCA ソフト | 本ツール |
| --- | --- | --- | --- |
| 対象 | 単一反応 | 任意の製品系 | 合成ルート同士の比較 |
| 出力 | 質量効率の指標 | 影響評価値 | 順位と逆転確率 |
| 前提の扱い | 暗黙 | 設定画面に分散 | 単一ファイルに宣言 |
| 再現性 | 保証なし | 手順依存 | ロックファイルで固定 |
| 必要データ量 | 少ない | 多い | 差集合のみ |
| 導入障壁 | 低い | 高い | 低い |

本ツールの立ち位置は、汎用 LCA ソフトの簡易版ではない。
比較という一つの問いに特化することで必要データを絞り込んだ、別種の道具である。

補足として、差分だけを見て共通部分を相殺する方式は、電子機器設計の分野で先例がある（DeltaLCA, arXiv:2311.09611）。
本ツールはその発想を合成ルートに持ち込む。

## 4. 使い方の想定

### 4.1 ラボでのルート選択

複数の合成経路が候補に挙がった段階で、各経路の物質収支を台帳に書き、順位を得る。
出力に含まれる逆転閾値により、どの条件を改善すれば順位が変わるかが分かる。
溶媒回収率をいくつ以上にすれば別ルートが優位になるか、といった形で返る。

### 4.2 論文や報告書の付録

台帳ファイルとロックファイルを添付することで、読者が同じ計算を再現できる。
査読において、前提の妥当性だけを議論の対象にできる。

### 4.3 調達や社内報告の一次スクリーニング

正式な PCF 算定に進む前に、どのルートを詳細評価にかけるかを絞り込む。
本ツールの出力は ISO 14067 準拠の算定結果ではない。
この点は出力の冒頭に明記すること。

## 5. スコープ

### 5.1 v0 でやること

- 線形の合成ルートの台帳の読み込みと検証
- 差集合の抽出
- 公開データによる係数の解決
- モンテカルロによる順位の確率評価
- 逆転閾値の探索
- 再現用ロックファイルの出力

### 5.2 v0 でやらないこと

- 収束型ルート（複数の分岐が合流する経路）
- 実験室規模から工業規模への外挿
- 廃棄段階と使用段階
- 温暖化以外の影響領域
- 言語モデルによる支援
- 逆合成による経路生成

やらないことは README に明記する。
できないことを曖昧にした結果を出さない。

## 6. データモデル

### 6.1 ルート台帳

入力は YAML 一ファイルとする。
以下を正準の形式とし、JSON Schema をリポジトリに含める。

```yaml
schema_version: "0.1"

assumptions:
  functional_unit: {mass_kg: 1.0, basis: product}
  boundary: cradle-to-gate
  grid_factor: {id: JP-2024, value_kgCO2e_per_kWh: 0.43, source: "..."}
  gwp_method: {name: IPCC-AR6, horizon_years: 100, feedbacks: false}
  solvent_recovery_default: 0.0
  waste_treatment: excluded

routes:
  merck:
    label: "公表ルート"
    steps:
      - id: 1
        yield: 0.82
        inputs:
          - {name: toluene, cas: "108-88-3", mass_kg: 12.0, role: solvent}
          - {name: "substrate A", cas: null, mass_kg: 1.0, role: reactant}
        electricity_kWh: 30.0
      - id: 2
        yield: 0.75
        inputs:
          - {name: 2-MeTHF, cas: "96-47-9", mass_kg: 8.0, role: solvent}
        electricity_kWh: 12.0
  denovo:
    label: "新規ルート"
    steps: [...]
```

規約を三点定める。

`mass_kg`：その工程で実際に投入した質量。機能単位への換算はツールが行う。
`role`：solvent、reactant、reagent、catalyst、auxiliary のいずれか。集計の内訳表示に用いる。
`cas`：可能なかぎり記入する。名称の揺れによる誤同定を避けるための主キーとして扱う。

### 6.2 係数表

再配布可能な公開データのみで構成する。
形式は CSV とし、一行が一物質に対応する。

必須列は、識別子（CAS または InChIKey）、名称、GWP 値（kgCO2e/kg）、出所、データベース版、地域、取得日、不確実性区分。

出所が異なる値を同一の表に混在させてよいが、出所列を空にした行は受け付けないこと。

## 7. 計算仕様

### 7.1 機能単位への換算

工程 `k` の投入質量を、その工程以降の累積収率で割り戻す。

```
factor_k = 1 / Π(yield_j)   for j >= k
adjusted_mass_ik = mass_ik * factor_k
```

累積収率がゼロを含む場合はエラーとして停止する。

### 7.2 溶媒の補給量

回収率 `r` が与えられた溶媒は、補給量 `mass * (1 - r)` を計算に用いる。
既定値はゼロであり、回収を仮定しない。
回収を仮定する場合は、その値が結論に与える影響を感度解析の対象に必ず含める。

### 7.3 排出量

背景データベースの値は製造段階までの GWP を 1 kg あたりで与えるため、行列を解く必要はない。

```
GWP_route = Σ_i (adjusted_mass_i * g_i) + Σ_k (electricity_k * factor_k * grid_factor)
```

`g_i` は係数表から解決した値である。

### 7.4 差集合

比較する二ルートについて、物質ごとに換算後の質量差をとる。
差がゼロの物質は解決の対象から外す。
解決に失敗した物質が差集合に含まれる場合のみ、警告を出す。
共通部分の解決失敗は結論に影響しないため、情報として記録するにとどめる。

### 7.5 不確実性

各係数 `g_i` に対数正規分布を割り当て、出所区分ごとに幾何標準偏差を設定する。

区分と既定値の対応は設定ファイル `uncertainty.yaml` に外出しする。
この既定値は本指示書では確定しない。
ecoinvent の pedigree matrix を参照して初期値を置き、**未検証の暫定値である旨をファイル冒頭に記載すること**。

モンテカルロの試行回数は既定 10000 とする。
この値も暫定であり、収束確認の手順を `docs/` に残すこと。

### 7.6 出力する統計量

- `P(GWP_A < GWP_B)`
- 差分の中央値と 90 パーセント区間
- 物質別および役割別の寄与内訳
- 解決の出所別の内訳（一次データが何割か）

`P` が 0.4 から 0.6 の範囲にある場合、順位を提示せず判定不能と表示する。
この閾値は設定可能とし、既定値の根拠が無いことを明記する。

### 7.7 逆転閾値

主要な仮定について一変数を振り、`P` が 0.5 を跨ぐ点を二分探索で求める。

対象とする変数は、溶媒回収率、電力の排出係数、各工程の収率とする。
跨がない場合は「この範囲では順位は変わらない」と返す。

## 8. CLI 仕様

```
carbonroute validate route.yaml
carbonroute resolve  route.yaml [--show-missing]
carbonroute compare  route.yaml --a merck --b denovo -o report.md
carbonroute lock     route.yaml -o route.lock.json
```

`validate` はスキーマ検証のみを行う。
`resolve` は係数の解決結果と欠損を一覧する。計算は行わない。
`compare` は比較を実行し報告書を出力する。
`lock` は係数表の版と解決結果を固定する。

すべての副作用はファイル出力に限る。
ネットワークアクセスは既定で無効とし、明示的な `--fetch` 指定がある場合のみ許可する。

## 9. 出力仕様

報告書の冒頭に、以下を必ず含める。

1. 本結果が ISO 14067 準拠の算定ではない旨
2. 適用した前提の全文
3. 係数表の版とハッシュ
4. 解決の出所別内訳

結論は順位と確率として提示する。
単一の絶対値を見出しに置かないこと。

## 10. 検証

**ベンチマークを実装より先に作る。**

工程ごとの寄与まで公開されている既存研究を試験集合とする。
候補として、レテルモビル合成の事例がある（doi:10.1021/jacs.5c14470）。
ただし、再現に必要な一次データが公開範囲で揃うかは未確認である。
揃わない場合は、順位の一致のみを合格条件とし、絶対値の一致は求めない。

回帰試験として、同一入力に対する出力の完全一致を継続的に検査する。
乱数種を固定し、浮動小数点の非決定性を排除すること。

## 11. リポジトリ構成と技術選定

```
carbonroute/
  src/carbonroute/
    schema.py        # pydantic モデル
    ledger.py        # 台帳の読み込みと換算
    resolve.py       # 係数の解決
    compute.py       # 排出量と差分
    uncertainty.py   # モンテカルロ
    sensitivity.py   # 逆転閾値
    report.py        # 報告書生成
    cli.py
  data/factors/      # 公開データ由来の係数表
  schemas/           # JSON Schema
  benchmarks/        # 再現試験
  docs/
```

Python 3.11 以上。
依存は pydantic、numpy、PyYAML、click に限る。
RDKit は物質同定の補助としてのみ用い、必須依存にしない。

コードのライセンスは MIT または Apache-2.0 とする。
係数表は元データのライセンスを継承するため、行ごとに出所とライセンスを保持し、混在を許す構成にすること。

## 12. 開発の順序

1. スキーマとバリデータ。台帳を書けるようにする
2. ベンチマーク一件の作成。合格条件を先に定める
3. 換算と排出量計算。決定論的な部分を完成させる
4. 係数表の初版。溶媒と汎用試薬に絞る
5. 差集合と不確実性
6. 逆転閾値と報告書
7. ドキュメントと公開

第 2 段階を飛ばさないこと。
検証手段の無いまま計算部を作ると、正しさを判断する基準が失われる。

---

## 13. 実装上の禁止事項

- 言語モデルに係数の数値を答えさせない
- 欠損値を既定値で黙って補完しない。欠損は欠損として報告する
- ecoinvent など再配布不可のデータをリポジトリに含めない
- 単一の絶対値を主要な結論として提示しない
- 出所不明の値を係数表に追加しない

## 15. 将来像

### 15.1 機能の拡張

v1 では収束型ルートに対応し、溶媒回収を明示的にモデル化する。
係数表に無い物質については、分子構造から製造段階の影響を推定するモデルを差し込み口として用意する。
この系統には FineChem がある（doi:10.1021/acssuschemeng.3c07038）。
推定値は出所区分として区別し、不確実性を大きく取る。

v2 では台帳を書く作業を支援する仕組みを加える。
実験ノートや文献から物質収支を抽出し、台帳の下書きを作る用途に限定する。
抽出結果は構造化スキーマに落とし、人の承認を経るまで計算に入れない。
係数の数値そのものを生成させることは、この段階でも行わない。

v3 では逆合成エンジンを接続し、生成した候補経路を自動でスクリーニングする。
ここまで到達すると、経路案から順位付きの候補一覧までが一続きになる。

### 15.2 本当に残るもの

長期的に価値を持つのは、実装ではなく次の三つである。

**台帳のスキーマ**：実験記録と環境評価をつなぐ共通の語彙。
**公開データによる係数表**：出所を明記し、誰でも検証と再配布ができる一枚。
**再現ベンチマーク**：主張の正しさを第三者が確かめられる試験集合。

電子実験ノートの出力先として台帳形式が採用され、複数の実装が同じベンチマークで比較される状態が最終的な目標である。
その状態に到達すれば、本ツール自体が置き換わっても構わない。
