# uslci.csv — sources, licence, and retrieval record

Generated by `scripts/ingest_uslci.py`. Re-read that script's module
docstring for the full retrieval procedure and the detailed reasoning

## What this is

Two rows, characterized cradle-to-gate GWP-100 (kg CO2e per kg) for:

| CAS | Substance | kgCO2e/kg |
|---|---|---|
| 630-08-0 | Carbon monoxide | 1.395 |
| 75-21-8 | Ethylene oxide | 1.833 |

Both come from the **U.S. LCI Database ("USLCI")**, distributed by the
**Federal LCA Commons** (National Renewable Energy Laboratory / Alliance
for Sustainable Energy, for the U.S. Department of Energy).

## Why only these two, and not the solvents this project actually wants

This is the important part; see the script's module docstring
("CHEMICAL COVERAGE") for the full account. In short:

- USLCI's toluene, methanol, sulfuric acid, sodium carbonate, sodium
  hydroxide, ammonia, hydrogen and acetic acid datasets exist, but every
  one of them is a **unit process** — its own direct emissions plus links
  to *other* unit processes (electricity, fuel combustion, transport, raw
  material extraction), not a finished cradle-to-gate number. Producing a
  genuine cradle-to-gate value means solving that whole linked system.
- That system-solve was attempted (built the reachable ~156-process
  technosphere subgraph and solved `(I - C) x = d` exactly with
  `numpy.linalg.solve`) and rejected: it produces numbers 50-150x higher
  than published literature for these chemicals (e.g. toluene ~103
  kgCO2e/kg, hydrogen ~1079 kgCO2e/kg). Root cause traced to
  `Fuel grade uranium, at regional storage`, which consumes ~4080 kWh
  electricity per kg (a legacy gaseous-diffusion-enrichment figure); that
  electricity is itself drawn partly from the U.S. grid mix's nuclear
  share, closing a loop that amplifies everything reachable through
  "Electricity, at grid" by one to two orders of magnitude. This looks
  like a real data-vintage mismatch inside USLCI, not a coding bug — but
  confirming and correcting it would mean auditing/patching a ~660-process
  database by hand, which is not something this project is willing to do
  silently inside an ingestion script. **No unit-process chemical from
  USLCI is used anywhere in this file, under any name.**
- That leaves USLCI's small set of pre-**aggregated** `LCI_RESULT`-type
  processes (elementary flows already summed across the whole upstream
  chain — crude oil, coal, natural gas etc. appear as direct elementary
  inputs, not further technosphere links). Of USLCI's 24 such processes,
  only three are chemicals: Hydrochloric acid, Carbon monoxide, and
  Ethylene oxide.
  - **Hydrochloric acid is included, and it disagrees with ADEME.**
    `data/factors/ademe_base_carbone.csv` carries CAS 7647-01-0 at
    1.199 kgCO2e/kg; this table gives 1.700, a factor of 1.42 apart. An
    earlier version of the loader refused to load two tables that
    disagreed, and this row was left out for that reason. The loader now
    records the disagreement as a `Conflict`, uses the value from the first
    table in sorted path order, and prints both in every report. Two
    independent public sources differing about the same substance measures
    how far openly available data spreads, which is worth more than a table
    that agrees with itself by construction. See `docs/data.md`.
- None of USLCI's aggregated processes are solvents (no THF, 2-MeTHF, DCM,
  ethyl acetate, acetone, ethanol, isopropanol, acetonitrile, DMF, DMSO,
  heptane). See `docs/sources-investigated.md` for the other sources
  probed instead, and for the (largely negative) result of that search.

## Exact endpoints used

- API guide (to find the endpoint shape): `GET
  https://www.lcacommons.gov/lca-commons-api-guide` — HTML page, fetched
  live 2026-08-26.
- Per-dataset fetch: `GET https://api.nal.usda.gov/FederalLCACommonsapi/
  browse/National_Renewable_Energy_Laboratory/USLCI_Database_Public/
  PROCESS/{refId}?api_key=...`, one call per target UUID (see
  `TARGET_PROCESSES` in the script). This is the officially documented
  "Download an Individual Dataset" endpoint.
- Retrieval date recorded per row is the date the individual process JSON
  was actually fetched from that endpoint (2026-08-26), not the date this
  CSV file was last regenerated from the on-disk cache — see the script's
  "CACHING / LIVE-FETCH NOTE" for why a cache exists here at all (the
  shared api.data.gov `DEMO_KEY` has a 50-request/day cap and was
  exhausted, confirmed live via an HTTP 429 `OVER_RATE_LIMIT` response with
  a multi-hour `Retry-After`, by this same investigation later the same
  day). Deleting `--cache-dir` and re-running with a personal key
  (`USLCI_API_KEY`) reproduces the fetch from scratch.

## Characterization factors applied

Every `LCI_RESULT` process reports raw elementary flows, not a
pre-computed GWP. Elementary output flows named "Carbon dioxide",
"Methane"/"Coalbed methane", or "Nitrous oxide" — the only greenhouse gases
present in either kept process — are characterized with IPCC AR6 WG1
100-year GWPs (GWP-100), fetched live as PDFs on 2026-08-26 and read with
`pdftotext -layout`:

| Gas | GWP-100 | Table / source |
|---|---|---|
| Carbon dioxide | 1 | Table 7.15, IPCC AR6 WG1 Ch. 7 main report |
| Methane (fossil) | 29.8 | Table 7.15, IPCC AR6 WG1 Ch. 7 main report |
| Nitrous oxide | 273 | Table 7.15 (identical to Table 7.SM.7) |

  - Chapter 7 main report: https://www.ipcc.ch/report/ar6/wg1/downloads/report/IPCC_AR6_WGI_Chapter07.pdf
  - Chapter 7 Supplementary Material (full gas table, used for gases not in
    Table 7.15 — not needed for these two rows, but shared by
    `GWP100_KGCO2E_PER_KG` in the script for completeness/reuse):
    https://www.ipcc.ch/report/ar6/wg1/downloads/report/IPCC_AR6_WGI_Chapter07_SM.pdf

USLCI does not split methane into fossil/non-fossil (a single "Methane"
flow, plus "Coalbed methane" which is unambiguously fossil); the
CH4-fossil factor (29.8) is used throughout, consistent with both
processes' methane being combustion-derived. No HFC/PFC/SF6 elementary
flows appear in either of the two kept processes.

## Residual (excluded) boundary

"Carbon monoxide, at plant" carries three small residual technosphere
exchanges not resolved by this script: 0.0025 MJ "Energy, fossil,
unspecified", 0.017 kg "Disposal, solid waste, process, to sanitary
landfill", 0.021 kg "Disposal, solid waste, fuel, to municipal
incineration". These are excluded rather than estimated, consistent with
this project's own default boundary (`waste_treatment: excluded`, see
`examples/route.yaml`); they are quantified in full in this row's `notes`
column and in `--report` output, not silently dropped. "Ethylene oxide, at
plant" has no residual technosphere exchanges at all.

## No `gsd`

Neither process publishes a coefficient of variation or other quantified
uncertainty for its inventory (checked: the `dqEntry`/`dqSystem` fields are
present but are a pedigree-style qualitative data-quality matrix, not a
numeric CV, and converting one to the other would be an invented
judgement call this project's rules don't allow). `gsd` is left empty on
both rows; `uncertainty_class = background_db` supplies the fallback GSD
(1.50) from `src/carbonroute/config/uncertainty.yaml`.

## Rejected candidates (recorded here per the project's reporting rules)

  disagreement with ADEME is reported rather than avoided.
- **Toluene, methanol, sulfuric acid, sodium carbonate, sodium hydroxide,
  ammonia, hydrogen (2 routes), acetic acid, ethanol (multiple biofuel

- **Xylenes, benzene, ethylene glycol, oxygen, propylene, styrene,

  system-solve problem; not pursued.
